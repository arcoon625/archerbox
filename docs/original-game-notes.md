# Original Sites project notes (historical)

These notes describe the source project before the independent Cloudflare migration. Hosting and sign-in instructions here are historical; use the root README for this repository.

# Archerbox
One website with 19 complete, locally bundled games, including Bearwatch: 100 Nights, Poop Panic, Jurassic Island, Snowball Showdown, Disaster Island, Laser Maze, Battle Arena, Creature Vault, Bakery Rush, Ninja Rooftops, Alpine Rush, Turbo Kart Racing, Rivals, Floor Is Lava, Color Rush, Baseball Blast, Touchdown Rush, Shark Racing and Hide and Seek. Games launch in a same-origin iframe beneath a persistent Back to Lobby toolbar. Only the active game loads; removing its iframe stops its renderer, input handlers and audio.

The lobby includes search, categories, favorites, recently played games, controls, fullscreen, shareable #play/game-id routes, and a browser-local lobby profile. Six games support two signed-in friends through the Friends panel. CPU modes and existing browser-local storage keys remain available. There is no public matchmaking or chat.

Floor Is Lava and Baseball Blast are snapshots of the sibling game projects. Games with friend multiplayer are maintained directly in public/games and preserved by the sync script. Run python3 scripts/sync-games.py to refresh those snapshots; it copies complete dist folders, shares the identical Three.js runtime, and preserves the shared lobby message bridge. Original standalone sites remain intact. The copy also injects a same-origin message bridge. The parent accepts messages only from its own active iframe. New external destinations are not used to launch games.

The active covers are browser captures of the actual game models, maps and materials, rendered with thumbnail cameras. The catalog uses the saved game captures in public/assets for the cards, recent games, details and featured hero. To recapture, copy scripts/cover-studio.html and scripts/cover-studio.js temporarily to public/_cover.html and public/_cover.js, serve public, select each scene and capture only the canvas. Remove the two temporary public files before publication. The old SVG posters and make-art.py are retained as the original artwork source. Three.js's MIT license is in public/vendor/LICENSE.txt.

The source games and hub are in `public/`; the Sites Vinext starter builds them into `dist/client` alongside the Worker. Run `npm run dev -- --port 5181` for a full local preview. A static server can preview the games but cannot provide Friends. Generated `dist/` output is ignored. The source manifest declares a `DB` D1 binding; publishing applies the generated schema migration before the Worker goes live. Run node tests/bundle.test.mjs to verify all game entry points, local imports, vendor files, navigation and catalog filtering. Site identity is in .openai/hosting.json.

Touchdown Rush uses four downs, ten-yard first downs, automatic receiver catches, possession changes, sprint stamina, jukes and tackles. Matches finish at 18 points or at the end of a play after the clock expires with a lead; tied matches continue in overtime. Run node tests/football.test.mjs for football rule validation. Touchdowns now trigger a six-second celebration with a close-up camera: Spike the Ball, Griddy, Touchdown Dance, Victory Pose or Backflip. Choose and preview a favorite in setup; click a move or press 1–5 during a celebration. The favorite is saved locally. Simulation and the game clock freeze during the animation, including the winning touchdown; Next Drive / See Final Score can skip it. CPU scorers also celebrate. Pause/resume preserves a match celebration. Run node tests/celebrations.test.mjs for animation and scoring checks.

Football uses 11 players per team: quarterback, five pass targets (three wide receivers, tight end, running back), and five offensive linemen. Defense has four rushers, three linebackers, two cornerbacks and two safeties. Pro is the default; All-Star increases pursuit prediction, coverage speed and tackle pressure, and Rookie preserves easier play.

Football customization offers all 32 NFL teams through a searchable picker, with recognizable color approximations, helmet abbreviation marks, scoreboard names and end zones. Team names were checked against the [NFL directory](https://www.nfl.com/teams/). Tennessee uses the light-blue home look announced in the [Titans March 2026 update](https://www.tennesseetitans.com/news/titans-unveil-new-uniforms-logo-to-represent-the-next-chapter-of-franchise-history). Real player names and usual numbers are bundled for all 32 clubs in `rosters.js`, from ESPN team depth charts and roster feeds, checked October 13, 2026. Every club has separate 11-player offensive and defensive game units, including when possession changes. The game uses a fixed 3-WR offense and four rushers/three linebackers; 3-4 charts are adapted using two edge linebackers and one reserve inside linebacker. These are game lineups, not an exact injury-adjusted starting lineup. Every selected player is checked against the team roster. Snapshots are updated explicitly with `scripts/update-football-rosters.py`, not live at runtime. Custom offensive numbers are saved per team; **Use Real Numbers** restores that club’s recorded numbers. Old fictional team selections fall back to Cowboys vs. Chiefs while preserving valid saved jersey numbers. Choose a different CPU opponent and jersey numbers 0–99. The quarterback number swaps with an existing teammate when needed; the roster editor validates 11 unique numbers. Customization is saved only in this browser.

Shark Racing is authored directly in the hub: four procedural shark models, three underwater loop tracks, two laps, five CPUs, Easy/Pro, boost rings, optional eye view, keyboard/touch steering and vertical swimming, and per-track personal bests saved in this browser. Course following and auto cruise keep beginners moving. `tests/shark.test.mjs` checks race outcomes, boosts, ring pickups, obstacles, boundaries and difficulty.

The Shark Racing models use smooth swept body surfaces, padded curved fins, recessed small eyes, five gill slits, countershaded skin with procedural grain, tiger striping and whale shark spotting. Distinct head and tail proportions are informed by [NOAA white shark anatomy](https://www.fisheries.noaa.gov/species/white-shark) and [NOAA shark identification](https://www.fisheries.noaa.gov/new-england-mid-atlantic/atlantic-highly-migratory-species/shark-identification-cooperative-shark-0). Body and tail deformation animate swimming; game sizes remain balanced for arcade racing. Original meshes and procedural textures are bundled, without loading external models or images.


## Hide and Seek

The eighth bundled game is an original, browser-local 3D hide-and-seek game. After-school Hideout, Maplewood Mansion, and Sunset City Park each have twelve hiding spots. Choose hider (one CPU seeker and four CPU hiders) or seeker (five CPU hiders). Hiders have eighteen seconds to hide and a hundred-second search; a player seeker starts after six seconds, with a hundred seconds on Easy or seventy-five on Pro. Hiders can hide/leave with E, sprint at the cost of being easier to notice, and move to another spot. Seekers search/tag with E and get a three-second map radar clue every fourteen seconds with Q. Pro CPU seekers move faster and spot exposed hiders farther away. Walls/furniture block both sight and tags. Models, hiding spots, maps, textures and covers are made from the game's own procedural assets. Friend play also supports one human seeker, one human hider, and four CPU hiders.

The shared map rectangles drive rendered obstacles, player collision, CPU grid paths, and line-of-sight checks. Every spot must be reachable from the spawn. CPU hiders reserve separate spots and give up a reservation if the user occupies it. Pause freezes rules and touch controls; blur or hidden pages pause automatically. View switches between chase and eye camera with V; drag the canvas to turn, and scroll to zoom. On touch screens, use the movement/sprint buttons and drag to turn.

Validation: `node tests/hide-and-seek.test.mjs` checks the thirty-six paths, collision sliding, blocked sight/tags, hider/CPU spot occupancy, both roles' outcomes, radar cooldown, and seeker pursuit on all three maps. `node tests/bundle.test.mjs` checks the eight-game catalog and packaged assets. Manually verified all maps, hiding, CPU search/tagging, eye view, radar, desktop movement, touch movement, and phone pause/menu layouts.


## Avatar studio

The lobby header, sidebar, and game toolbar open the original Archerbox Avatar studio at `#avatar`. It includes exactly 300 free catalog items: fifty each for headwear, face accessories, shirts, pants/shorts, shoes and pets. Each item has a procedural 3D model or clothing texture/shape recipe and a rendered thumbnail; thumbnails load as their cards become visible. All six slots can be removed. Eight skin tones, six expressions, drag/arrow-key rotation, zoom, stand/wave/dance poses, and random complete combinations support mixing outfits. The desktop preview stays in place while the wardrobe scrolls; the phone layout includes a View avatar button.

Save avatar stores the look and a small profile portrait locally in the current browser. Back to games also saves the current look. Up to twelve named outfits can be saved, loaded, overwritten by name, or removed. Data is validated on read, invalid item IDs cannot equip another category, names are escaped before rendering, corrupt storage falls back safely, and failed saves show a message. No shop currency, purchases, account backend, or external 3D models are used.

The saved outfit and decorative companion appear on the human player in Hide and Seek and Color Rush. Pets move with the avatar and have no collision, scoring, combat, or survival effects. Hide and Seek hides the whole avatar/pet when hiding or in eye view; Color Rush preserves its camera, movement and tile rules. Sports uniforms and the nonhuman racers keep their own character models.

Validation: `node tests/avatar.test.mjs` checks exactly fifty items per category, three hundred unique IDs/names, finite geometry for every 3D preview and fifty complete combinations, saved outfits, invalid/corrupt saves, search, and storage failures. Texture rendering is verified in the browser. Also run `node tests/bundle.test.mjs` for the site/game assets and `node tests/hide-and-seek.test.mjs` for the existing game rules. Manually verified matching outfit selection in all categories, saving/reloading, named outfit loading, the profile portrait, both supported games, and phone wardrobe/preview/lobby layouts.


### Avatar realism update

All 300 wardrobe IDs and saved outfits are retained. The avatar now uses a shaped oval head, eyes with irises/highlights, ears, a nose, a tapered torso, curved limbs, palms/fingers/thumbs, and the existing expression and pose controls. Clothing prints follow the curved torso/legs; fabric weave, denim, knit, leather, seams, cuffs, buttons, shoe eyelets and rubber tread use physical materials and procedural detail. Accessories have rounded manufactured edges, cap panels/stitching, knit ribs, cushions, hinges, filters and clearer coated lenses. Metal, cloth, skin, fur, rubber, plastic and scales have their own roughness and bump textures.

Studio lighting includes a procedural reflection environment for both the live avatar and thumbnails. Pet previews use a fitted three-quarter camera. Mammals have muzzles, whiskers, dark fur eye patches and instanced fur tufts; fantasy creatures have claws, noses, and wing ribs; robots have fasteners. The four shark species use the same detailed procedural meshes as Shark Racing, scaled as companions, with tail swimming. These are original game models with a more realistic material treatment, rather than photographs or scans.

The existing 300-item model tests now also check finite rounded normals, physical surface textures, and outward-facing torso geometry. Browser QA checks the outfit preview, accessory fit, thumbnails, saved look, phone layout, and the avatar in a bundled game.


Friends uses Sites sign-in IDs and D1, with no email addresses exposed in the game. Profile → Friends shows the friend list, a stable 10-character alphanumeric code, code entry, and game/arena choices with Accept/Decline invitations. Codes are unique case-insensitively, omit ambiguous characters, and the insert atomically rejects any code within two character changes of an existing code. Entering a code adds the mutual friendship. Profile names/colors persist with the account; favorites, recent games, avatars and outfits remain browser-local. Friends must have hosting permission to open the site. Publication preserves the existing private audience.

Live play supports Turbo Kart Racing (two friends plus four CPUs), Shark Racing (two friends plus four CPUs), Color Rush (two friends plus six CPUs), Hide and Seek (one friend seeks, one hides, four CPU hiders), Touchdown Rush (opposing 11-player teams with CPU teammates), and Rivals (battle each other or team up against CPUs). Floor Is Lava and Baseball Blast keep their existing modes. Rivals retains the `neon-clash` route so old links and favorites still work.

Choose a game and arena in Profile → Friends, invite a friend, and both choose Ready after customizing their kart, shark, team, or weapons. The host chooses shared difficulty/pace, seeker role, and Rivals team size. Each friend has independent controls and loadout/team choices. The server owns movement, collision, hits, scores, shared boards, hidden spots, and match results. Inputs and actions are bounded, event IDs are deduplicated, and hiding spots are removed from a seeker's snapshot until visible or revealed by radar. JSON round trips preserve random state and sets. A single controlling tab per account prevents duplicate-tab interference; Play in This Tab takes over after a reload.

Snapshots travel over same-origin HTTP polling; Turbo Kart and Rivals interpolate positions. Pausing stops your inputs while the shared match continues. A disconnected player closes the room after 60 seconds; leaving through the lobby closes it immediately. Rooms expire after fifteen minutes. Friends need permission to open the hosted site; publication preserves its private audience.

Football has a Punt play, a P shortcut, automatic return catches, playable punt returns, touchbacks to the 20, and kickoffs after non-winning touchdowns. Sprint and juke use the normal controls. Returns can score six points and trigger the selected celebration. A stopped return starts a fresh first-and-ten. CPU teams can punt on fourth down. Kicking uses arcade timing and the existing eleven-player units; it is not a full NFL special-teams simulator. Both friends see the same ball, possession, returner, score and celebration.

Run `node tests/multiplayer.test.mjs` for all five new friend modes, every arena, independent human inputs, shared matches and results, hiding privacy, football passes/teams/celebrations, and Rivals collisions/combat/grenades/respawns/team-up. Run `node tests/football-kicks.test.mjs` for punts, kickoffs, touchbacks, returns, return touchdowns, and friend return control.
Run `node tests/friends.test.mjs` for real SQLite-backed API tests across 35 accounts and complete races on all four tracks. For optional two-player browser QA, run `ARCHERBOX_TEST_PLAYERS=1 npm run dev -- --port 5181`: loopback sign-in at 127.0.0.1 uses the starter’s local Seedy account, while localhost uses a separate Nova test identity. This middleware requires local sign-in, only runs on loopback in opted-in dev mode, and is excluded from production. No test profiles or friendships are seeded into hosted migrations.

Football running plays: Inside Run (3), Sweep Left (4), Sweep Right (5), alongside Long Pass (1), Quick Slant (2) and Punt (P). Handoffs start four yards behind the line. Linemen and downfield teammates choose separate blocking targets; swept body collision prevents defenders crossing blockers, shorter engagements allow lateral movement, defenders can push blockers back or escape, and physical bodies prevent tackles through a blocker. Front-facing contact and player roles affect engagement duration. A defender can still tackle a reachable runner on their side of contact. Blocking teammates use normal teammate speeds, so gaps close and runs are not guaranteed first downs. The same rules run CPU and friend matches; engagement actor IDs are remapped in guest views. Block poses, green BLOCK name tags and a live run-yard counter show the action. Run `node tests/football-blocking.test.mjs` along with the football, kicks and multiplayer tests. Research, sources and a repeatable before/after run comparison are in `docs/nfl-blocking-notes.md`.

Football helmets are original procedural geometry in `public/games/touchdown-rush/helmets.js`: a hollow molded shell, smooth ear/crown openings with edge trim, recessed padding, powder-coated role-specific face cages, four flat chin straps, chin cups, mounting screws, conformal stripes and curved team decals. Silver shells use a metallic finish. Helmet parts merge onto the existing animated head to preserve the per-player draw budget, with no changes to collisions or gameplay. The catalog cover is recaptured from actual game models. `scripts/football-helmets.*` provides reproducible front/side/rear preview views; temporarily copy these to `public/_football-helmets.*` to render, then remove those public copies.

Field goals and extra points: F or the playbook opens a three-point field-goal attempt; touchdowns first offer a celebration, then a one-point PAT, then a kickoff. A/D adjusts aim, W/S changes power, and Space kicks; sliders and the Kick button work with mouse/touch. The colored trajectory preview uses the same ballistics and post-clearance checks as scoring. The stadium and rules share goal-post dimensions. Short or wide attempts score nothing; a missed field goal turns over possession, while either PAT result leads to a kickoff. CPU teams take field goals on fourth down within 58 yards and attempt their PATs. First to 21 points wins, or lead after the three-minute clock expires; a touchdown at zero still gets its try, and ties continue in overtime. Setup also offers repeatable 40-yard Practice Field Goals with no running clock. These kicks use the existing eleven-player units and arcade aiming rather than a full special-teams simulation.

`node tests/football-placekicks.test.mjs` checks made/missed field goals and PATs, both scoring directions, post-plane clearance, range, possession, kickoffs, CPU choices, overtime, practice, duplicate kicks and shared friend scoring/aim permissions. Existing football, return, blocking, celebration and multiplayer regressions include the new PAT sequence. Touchdown celebrations are triggered by touchdown events, so field goals and extra points cannot start a second dance.

Stadiums and fans: `public/games/touchdown-rush/stadium.js` builds two-tier stands on all four sides, molded seats, aisle steps, safety rails, concourse entrances, canopies, glass suites, entry tunnels, padded walls, benches, coolers and floodlight banks. Both jumbotrons show the live score and game/practice clock. Decorative structures stay outside the field and preserve all rules.

Expanded football playbook: `public/games/touchdown-rush/playbook.js` contains thirteen calls grouped as six passes, five runs and two kicks. Curl Routes (6) turn back after the stem; Corner Strike (7) breaks toward the sideline; Crossing Routes (8) crosses receivers at different depths; RB Screen (9) sends the back into the flat behind the line. Shared waypoint sampling moves the receivers and leads passes along their actual routes. Counter Run (0) starts left and cuts right; QB Draw (Q) keeps the quarterback as the controlled runner, supports jukes, and records tackles rather than sacks. CPU teams and both friend seats use the same calls. Original keys 1–5, Punt P, Field Goal F, extra points, and kick practice remain. After the snap, keys 1–5 still select receivers. The on-field playbook has Pass, Run and Kick section buttons and remembers the chosen section between drives.

Passing outcomes: passes follow a descending arc and are sampled along their flight path at catchable heights, including with coarse simulation steps. A receiver who reaches the ball can complete the pass; a defender set in the passing lane can make a clean interception, while reaching or contested contact can knock it away for an incompletion. Uncaught or out-of-bounds balls are incomplete, return to the original line, and use a down, including turnover on fourth down. Interceptions stop play and give the defense first and ten at the catch spot; catches in the defense’s end zone become touchbacks at its 20. All thirteen plays and all kicks remain. Pressure, running and very long throws introduce repeatable accuracy error saved with the ball, while open stationary short throws stay accurate. OPEN/COVERED/RISKY target labels and pressure advice help explain the risk. Incomplete balls visibly fall and bounce; interceptions show the named defender holding the ball. Result banners, next-possession text and match stats distinguish completions, incompletions, interceptions caught and interceptions thrown. Friend snapshots remap all result actor/team IDs, and only the offense can choose its receiver.

Run `node tests/football-passing.test.mjs` for open catches, eligible receivers, ground/out-of-bounds misses, defensive breakups, midflight interceptions, height/reach, fourth downs, touchbacks, both directions, three step sizes, deterministic throw error, exact-once stats and serialized friend outcomes.

A dated real-world NFL roster is not used in fantasy. Original CPU stars are explicitly simulated. The server records immutable, deduplicated results after the authoritative game ends; clients cannot submit scores. Added football stats distinguish passing, rushing and receiving yards/TDs and sacks. CPU weekly results are deterministic per league/player/week. Separate device-local practice leagues let users advance a whole six-week season without waiting or writing demo scores to saved leagues.
